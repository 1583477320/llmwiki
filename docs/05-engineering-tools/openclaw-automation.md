# OpenClaw 桌面自动化

> 动作空间设计与屏幕视觉闭环 —— Agent 操作 GUI 的核心范式

## 什么是桌面自动化 Agent？

桌面自动化 Agent 能够像人类一样操作图形用户界面（GUI）—— 观看屏幕、移动鼠标、点击按钮、输入文字。这是 Agent 从纯文本交互走向真实生产环境的关键能力。

### 核心能力

- **屏幕理解**：识别窗口、按钮、文本框、图标等 UI 元素
- **动作执行**：鼠标移动、点击、拖拽、滚轮；键盘输入、快捷键
- **状态验证**：执行动作后验证界面变化是否符合预期
- **错误恢复**：处理弹窗、加载延迟、意外跳转等异常

## 动作空间设计

动作空间（Action Space）定义了 Agent 可以执行的所有操作。

### 鼠标动作

```json
{
  "type": "mouse",
  "action": "click" | "double_click" | "right_click" | "move" | "drag",
  "position": {"x": 100, "y": 200},
  "button": "left" | "right" | "middle"
}
```

### 键盘动作

```json
{
  "type": "keyboard",
  "action": "type" | "press" | "hotkey",
  "text": "要输入的文本",
  "keys": ["Ctrl", "C"]
}
```

### 复合动作

```json
{
  "type": "composite",
  "actions": [
    {"type": "mouse", "action": "move", "position": {"x": 300, "y": 400}},
    {"type": "mouse", "action": "click"},
    {"type": "keyboard", "action": "type", "text": "Hello World"}
  ]
}
```

::: tip 动作粒度设计原则
动作空间应当处于「语义有意义」的粒度层级。过于底层（每个像素位移）会导致规划步数爆炸；过于高层（「填写表单」）则失去灵活性。将常用模式封装为 Shortcut Action（如 `scroll_to_bottom`, `screenshot`）是实用的平衡策略。
:::

## 屏幕视觉闭环

### 感知-行动闭环

```
Screen Capture → [LMM 视觉理解] → 决策 → 执行动作 → Screen Capture → ...
```

每一步动作执行后，都需要通过新的屏幕截图验证结果，而非盲目信任。

### 视觉定位策略

如何将「点击登录按钮」转化为像素坐标？

| 策略 | 描述 | 精度 |
|------|------|------|
| **Visual Grounding** | 模型直接输出边界框坐标 | 中等 |
| **Set-of-Mark** | 为每个 UI 元素标注数字标签 | 高 |
| **OCR-based** | 通过文字识别定位元素 | 高（文本元素） |
| **Accessibility Tree** | 读取系统的无障碍元素树 | 极高（需系统支持） |
| **Hybrid** | 结合上述多种策略 | 最高 |

### UI 元素检测范式

```
原始截图
  │
  ├──→ UI 元素检测模型 (OmniParser / UGround / ShowUI)
  │      │
  │      └──→ 结构化 UI 元素列表：[{id, type, bbox, text}, ...]
  │
  ├──→ LMM 推理：「用户想登录」→ 应点击 id=7 的元素
  │
  └──→ 坐标映射：id=7 → bbox(320, 240, 380, 270) → 中心点 (350, 255) → 点击
```

## 关键工程挑战

### 1. 异步与等待

GUI 操作天然异步 —— 点击按钮后页面需要加载时间：

```python
# 错误做法
click("提交按钮")
type("下一页的输入框", "内容")  # 页面可能尚未加载

# 正确做法
click("提交按钮")
wait_for("下一页的输入框", timeout=10_000)
type("下一页的输入框", "内容")
```

### 2. 多模态 Context 管理

屏幕截图是高分辨率图像，产生大量视觉 Token：

- **压缩策略**：截取仅相关区域（如当前活动窗口）
- **分辨率权衡**：1080p 对 UI 理解通常已足够
- **变化检测**：仅当屏幕有显著变化时重新编码视觉信息

### 3. 安全沙箱

桌面自动化 Agent 拥有极高权限，必须加以限制：

- **动作白名单**：只允许预定义的合法操作集
- **操作确认**：高风险操作（如删除、提交）需用户确认
- **虚拟化隔离**：在 Docker/VM 中运行 Agent

## OpenClaw 架构概览

OpenClaw 是典型的桌面自动化 Agent 框架，架构如下：

```
┌─────────────────────────────────────────┐
│              用户指令                     │
└──────────────────┬──────────────────────┘
                   │
┌──────────────────▼──────────────────────┐
│         Planner (语言规划)                │
│   任务分解为子目标和动作序列                │
└──────────────────┬──────────────────────┘
                   │
┌──────────────────▼──────────────────────┐
│         Actor (动作执行)                  │
│   鼠标/键盘控制 + 截图 + 无障碍 API        │
└──────────────────┬──────────────────────┘
                   │
┌──────────────────▼──────────────────────┐
│         Observer (视觉感知)               │
│   LMM 屏幕理解 + UI 元素检测 + OCR         │
└──────────────────┬──────────────────────┘
                   │
┌──────────────────▼──────────────────────┐
│         Verifier (结果验证)               │
│   动作前后的屏幕对比 + 断言检查              │
└─────────────────────────────────────────┘
```
